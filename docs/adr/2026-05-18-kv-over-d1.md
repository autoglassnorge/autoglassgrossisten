# ADR: KV over D1 for katalog-lagring

## Kontekst

Autoglass AS trenger rask lagring av 30 000+ bilglass-poster for oppslag via Cloudflare Worker.
Hver post inneholder ~25 felter (eurocode, brand, model, flaggs, etc.).

## Problem

Hvilken Cloudflare-lagringsteknologi skal brukes for katalogen?

## Alternativer

### 1. Cloudflare KV (valgt)
- **Pros:** Ingen cold start, global replikering, enkel API, kostnadseffektiv
- **Cons:** Eventuell konsistens (opptil 60s), 25 MiB per verdi-limit, ingen spørringer
- **Kostnad:** ~$0

### 2. Cloudflare D1
- **Pros:** SQL-spørringer, indekser, relasjonell modell
- **Cons:** Beta, cold starts (~100ms), mer kompleks migrering
- **Kostnad:** ~$0 (beta)

### 3. Begge (KV som cache, D1 som master)
- **Pros:** Best av begge verdener
- **Cons:** Dobbel kompleksitet, dobbelt vedlikehold

## Valg

**KV** — for nå.

D1 er fremtidig når vi trenger komplekse spørringer (f.eks. "alle Volvo V90 2020-2023 med ADAS og regnsensor"). Foreløpig er KV tilstrekkelig og raskere.

## Konsekvenser

- Katalog må splittes i chunks (< 25 MiB)
- Oppslag gjøres i minnet (loadCatalog + filter)
- D1-migrasjon planlegges i Q3 2026
